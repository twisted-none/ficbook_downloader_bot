# Ficbook Telegram Bot

Telegram-бот на `aiogram`, который принимает ссылки на поддерживаемые литературные сайты, загружает текст, собирает выбранные пользователем форматы и отправляет файлы в ответ.

## Возможности

- принимает ссылки Ficbook, AO3, Wattpad, Hogwartsnet, RanobeLIB и Litnet
- раскрывает HTTPS-ссылки share.google только до поддерживаемых работ, с проверкой DNS и ограничениями запросов
- уточняет назначение ссылки в режиме поддержки: скачать фанфик или отправить сообщение администратору
- скачивает публичные книги RanobeLIB без аккаунта, включая обложку и выбранные главы
- скачивает бесплатные книги Litnet и сразу сообщает, если книга платная
- скачивает многоглавные фанфики по главам
- скачивает AO3 целым HTML-файлом через Download, с резервной загрузкой по главам
- умеет скачивать только выбранные главы в формате `1,2,5-10,17`
- добавляет обложку в `fb2`, `epub`, `docx` и `pdf`, если она есть у фанфика
- собирает итоговые `fb2`, `epub`, `txt`, `docx` и `pdf` в памяти
- добавляет реальные номера страниц в `docx` и `pdf`
- сохраняет в DOCX жирный/курсив, цитаты, списки, оглавление, метаданные и примечания
- добавляет в EPUB оглавление, расширенные метаданные и оформление примечаний
- сохраняет пейринги и интерактивные примечания Ficbook
- различает авторов и переводчиков Ficbook и формирует единый вводный блок без повторов
- сохраняет внутренние ссылки и сноски всех поддерживаемых сайтов в EPUB, FB2, DOCX и PDF
- создаёт кликабельное оглавление и ссылки возврата от примечаний; в TXT сохраняет текстовое оглавление
- позволяет выбрать форматы и включить выбор отдельных глав через `/settings`
- показывает команды в меню Telegram рядом с полем ввода сообщения
- позволяет включать или выключать добавление обложки через `/settings`
- позволяет написать администратору через `/help`
- использует отдельные очереди для сайтов и каждого Ficbook-аккаунта
- показывает позицию, примерное ожидание и прогресс скачивания
- сохраняет базовое форматирование EPUB: главы, абзацы, списки, цитаты, жирный и курсивный текст
- пишет аналитику пользователей и скачиваний в PostgreSQL
- отдаёт Prometheus-метрики на `/metrics` для Grafana/Prometheus
- поддерживает авторизацию для `18+` через переменные логина и пароля нужного сайта
- распределяет Ficbook-задания циклически между пятью аккаунтами
- переносит задание на следующий Ficbook-аккаунт при `429` или ошибке входа
- готов для запуска в Docker

## Запуск

```bash
cp .env.example .env
docker compose up --build -d
```

## Переменные окружения

- `BOT_TOKEN` — токен Telegram-бота
- `FICBOOK_LOGIN` — логин Ficbook для `18+`
- `FICBOOK_PASSWORD` — пароль Ficbook для `18+`
- `FICBOOK_BACKUP_LOGIN` — запасной логин Ficbook для повторной попытки при `429`
- `FICBOOK_BACKUP_PASSWORD` — пароль запасного Ficbook-аккаунта
- `FICBOOK_ACCOUNT_3_LOGIN`, `FICBOOK_ACCOUNT_3_PASSWORD` — третий Ficbook-аккаунт
- `FICBOOK_ACCOUNT_4_LOGIN`, `FICBOOK_ACCOUNT_4_PASSWORD` — четвёртый Ficbook-аккаунт
- `FICBOOK_ACCOUNT_5_LOGIN`, `FICBOOK_ACCOUNT_5_PASSWORD` — пятый Ficbook-аккаунт
- `AO3_LOGIN`, `AO3_PASSWORD` — необязательный аккаунт AO3 для доступных ему произведений
- `WATTPAD_LOGIN`, `WATTPAD_PASSWORD` — логин и пароль Wattpad, если работа требует вход
- `HOGWARTSNET_LOGIN`, `HOGWARTSNET_PASSWORD` — логин и пароль Hogwartsnet для закрытого доступа
- `LITNET_LOGIN`, `LITNET_PASSWORD` — необязательные данные Litnet; бесплатные книги работают без входа
- `RANOBELIB_LOGIN`, `RANOBELIB_PASSWORD` — аккаунт RanobeLIB для закрытых глав
- `FICBOOK_MAX_CONCURRENT_DOWNLOADS` — устаревшая совместимая настройка; параллельность определяется аккаунтами
- `FICBOOK_DOWNLOAD_INTERVAL_SECONDS` — минимальная пауза между стартами скачиваний, по умолчанию `8`
- `FICBOOK_REQUEST_DELAY_SECONDS` — пауза между запросами к Ficbook внутри одного скачивания, по умолчанию `1.5`
- `FICBOOK_RETRY_ATTEMPTS` — число попыток на аккаунт при `429`, по умолчанию `3`
- `FICBOOK_RETRY_BASE_DELAY_SECONDS` — первая пауза backoff при `429`, по умолчанию `8`
- `FICBOOK_RETRY_MAX_DELAY_SECONDS` — максимальная пауза backoff при `429`, по умолчанию `45`
- `ADMIN_CHAT_ID` — ваш `chat_id` для уведомлений об ошибках пользователей
- `ALERT_BOT_TOKEN` — отдельный бот для админских уведомлений, если нужен
- `PREMIUM_QUEUE_USER_IDS` — user id через запятую, которые проходят очередь первыми
- `LOG_LEVEL` — уровень логирования, по умолчанию `INFO`
- `DATABASE_URL` — PostgreSQL DSN для аналитики
- `METRICS_PORT` — внутренний порт HTTP endpoint `/metrics`, по умолчанию `8000`
- `METRICS_HOST_PORT` — порт на хосте для `/metrics`, по умолчанию `18000`
- `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` — параметры PostgreSQL, если база запускается отдельно
- `POSTGRES_HOST_PORT` — локальный порт PostgreSQL для Grafana datasource, по умолчанию `15432`

## Поведение

Бот отвечает на сообщение со ссылкой на фанфик и отправляет выбранные пользователем форматы. По умолчанию включены `.fb2`, `.epub`, `.txt`, `.docx` и `.pdf`; изменить выбор можно командой `/settings`. В настройках есть отдельные разделы для форматов файлов и обложки. Там же можно включить выбор отдельных глав: после ссылки бот спросит номера глав, а пользователь отвечает, например, `1,2,5-10,17` или `0` для всех глав. Если фик `18+`, но логин или пароль не заданы, бот вернет понятную текстовую ошибку вместо технического сообщения. Если задан `ADMIN_CHAT_ID`, бот дополнительно пришлет вам сообщение с данными пользователя и текстом ошибки.

Для каждого сайта используется отдельная очередь, а для каждого заполненного Ficbook-аккаунта создаётся собственная однопоточная очередь. Ficbook-ссылки распределяются циклически по аккаунтам. Ожидающий пользователь видит только своё место и пересчитываемое время, а активная загрузка обновляет процент не чаще одного раза в 5 секунд. Оценка ожидания использует две минуты на один фанфик. Команда `/queue` доступна только администратору и показывает суммарное число активных и ожидающих фанфиков.

Бот не обходит CAPTCHA, оплату или ограничения доступа. Публичные произведения AO3 и бесплатные книги Litnet скачиваются без входа. Если Ficbook показывает страницу технических работ, активные задания остаются в очередях и автоматически продолжаются после восстановления сайта.

Ссылки Hogwartsnet, включая старые HTTP-ссылки, скачиваются через HTTPS с проверкой сертификата. Авторизация также выполняется только по HTTPS; переходы на HTTP, другой домен или нестандартный порт блокируются. При ошибке TLS бот сообщает о проблеме без повторной отправки пароля по HTTP.

### Защита запросов Litnet и RanobeLIB

Для этих двух клиентов используется `src/sources/safe_http.py`:

- Только HTTPS на порту 443, с проверкой сертификата и имени сервера. Адреса с логином/паролем,
  управляющими символами и локальные протоколы (`file:`, `data:`, FTP) запрещены.
- Проверяются все DNS-ответы IPv4/IPv6. Внутренние, loopback, link-local, multicast,
  зарезервированные и переходные адреса IPv6 блокируются. Подключение идёт к проверенному
  числовому IP без повторного разрешения имени; TLS по-прежнему проверяет исходный домен.
- Каждый редирект проверяется до нового подключения; допускается максимум пять переходов.
  Тело ответа редиректа не загружается. POST не переносится на другой хост.
- Страницы Litnet ограничены `litnet.com` и `www.litnet.com`; пароль отправляется только
  на `https://litnet.com/auth/login`. API и обмен токенами RanobeLIB ограничены
  `api.cdnlibs.org`, вход — `auth.lib.social`. OAuth callback проверяется по точному
  домену и пути `https://ranobelib.me/ru/front/auth/oauth/callback`, а также по `state`.
  Callback перехватывается без отправки запроса на него.
- Обложки загружаются отдельным клиентом без cookies авторизации и токенов. Разрешены публичные
  HTTPS-CDN; размер ограничен 8 MiB. Небезопасная или недоступная обложка пропускается,
  скачивание книги продолжается. Ошибки безопасности не содержат исходных URL и секретов.

Настроенный для HTTPS-запросов HTTP-прокси не отключается: сохраняется обнаружение настроек
`urllib` и `NO_PROXY`. Прокси получает `CONNECT` к проверенному числовому IP назначения,
а проверка сертификата остаётся привязана к исходному домену. Сам явно настроенный прокси
может находиться в локальной сети; адрес сайта назначения всё равно должен быть публичным.
Если прокси запрещает `CONNECT` к IP или использует неподдерживаемый здесь протокол SOCKS/HTTPS,
запрос завершается ошибкой без скрытого перехода на прямое подключение. В такой конфигурации
нужно отдельно согласовать поддержку прокси; нельзя отключать защиту DNS или TLS.

Эти ограничения пока не распространяются на остальные адаптеры FanFicFare и Google share resolver:
у них отдельные HTTP-клиенты и политики. Общие ограничения размеров HTML/JSON, очередей
и потребления памяти относятся к следующему этапу защиты от перегрузки.

## Структура проекта

```text
src/
├── bot/          # Telegram handlers, keyboards and session types
├── core/         # configuration, models, chapter parser and queues
├── sources/      # Ficbook, RanobeLIB, Litnet and source URL adapters
├── exporters/    # FB2, EPUB, TXT, DOCX and PDF generation
├── storage/      # PostgreSQL analytics and user settings
├── monitoring/   # Prometheus metrics endpoint
└── main.py       # application entry point
```

Секреты хранятся только в локальном `.env`. В Git добавляется `.env.example` с пустыми или демонстрационными значениями.

## Аналитика

Данные хранятся в PostgreSQL:

- `bot_users` — пользователи Telegram, `/start`, username, full name, first/last seen.
- `downloads` — попытки скачивания, статус `attempt/success/error`, URL, название фанфика, ошибка.
- `user_format_settings` — выбранные пользователями форматы, обложка и режим выбора глав.

Готовые view для Grafana PostgreSQL datasource:

- `analytics_summary` — всего пользователей `/start`, активные за 30 дней, попытки, успешные скачивания, success ratio.
- `analytics_users` — username, full name, количество скачанных фанфиков за всё время, последняя ссылка за срок хранения истории.
- `analytics_top_fanfics` — топ-5 фанфиков по успешным скачиваниям.

Подключение Grafana к PostgreSQL с хоста:

- Host: `localhost:15432`
- Database: `ficbook_bot`
- User: `ficbook`
- Password: значение `POSTGRES_PASSWORD`

Prometheus endpoint:

- `http://localhost:18000/metrics`

Основные метрики:

- `ficbook_bot_started_users_total`
- `ficbook_bot_active_users_30d`
- `ficbook_bot_download_attempts_total`
- `ficbook_bot_successful_downloads_total`
- `ficbook_bot_download_success_ratio`
- `ficbook_bot_top_fanfic_downloads`

В `/metrics` больше не передаются Telegram ID, username, имена, названия произведений и ссылки.
Топ содержит только позиции `rank` и количество скачиваний. Персональная метрика
`ficbook_bot_user_downloads_total` удалена; панели с ней нужно перевести на закрытый PostgreSQL datasource
и view `analytics_users`. Метрики кешируются на 30 секунд; параллельные запросы используют один снимок,
а обращения к БД не блокируют обработку сообщений бота. Ограничения firewall по IP сохраняются:
сами `/metrics` и `/health` не требуют авторизации.
При ошибке БД `/metrics` возвращает общий ответ `503` без внутренних деталей и делает паузу
5 секунд перед новой попыткой, чтобы частые запросы не усиливали сбой.

### Хранение персональной истории

Срок по умолчанию — **30 дней** (`HISTORY_RETENTION_DAYS=30`, минимум 30, чтобы сохранять
точность `active_users_30d`). Бот проверяет истёкшую историю при запуске и затем раз в сутки.
Связь скачивания с Telegram ID и текст ошибки удаляются в течение суток после истечения срока.
У неактивных пользователей очищаются username и full name после такого же срока с последнего обращения.

Сохраняются:

- общее количество пользователей, попыток, успешных скачиваний и соотношение успехов за всё время;
- накопленное количество скачиваний каждого пользователя, его Telegram ID для настроек и рассылок;
- статусы, даты и публичные адреса произведений без дополнительных query-параметров (у Hogwartsnet остаётся `fid`);
- статистика произведений и пользовательские настройки.

Это удаление персональной связи с историей, а не полное удаление данных пользователя.
Строки скачиваний остаются в БД; пользовательские счётчики архивируются в одной транзакции
с очисткой связи. Повторная очистка не увеличивает их повторно. Старые завершённые записи
после очистки нельзя изменить вызовом `finish_download` или удалить через `discard_download`.

Миграция схемы выполняется при запуске нового бота, но **ранее накопленная история не очищается автоматически**.
После обновления схемы её можно отдельно включить в политику хранения. Сначала проверить количество:

```bash
docker compose exec ficbook-bot python -m src.storage.retention --enroll-existing
```

Без `--apply` команда только показывает количество записей, не изменяя схему или данные.
После проверки и резервного копирования явно применить к существующей истории:

```bash
docker compose exec ficbook-bot python -m src.storage.retention --enroll-existing --apply
```

Записи старше 30 дней будут очищены, более свежим будет назначено истечение через 30 дней
от исходной даты. Для ручной очистки только уже включённой истории:

```bash
docker compose exec ficbook-bot python -m src.storage.retention --apply
```

Нельзя откатывать код на версию, не учитывающую `archived_successful_downloads`: её пользовательская
статистика будет занижена после первой очистки. Перед обновлением сохраняйте резервную копию;
не запускайте старую и новую версии бота одновременно. Очистка не затрагивает копии БД,
старые логи и уже собранные персональные серии в Prometheus/Loki: срок хранения этих систем
нужно настроить отдельно.

Проверка на отдельной локальной тестовой БД (не рабочей):

```powershell
$env:FICBOOK_TEST_DATABASE_URL = 'postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:TEST_PORT/ficbook_security_test'
.venv/Scripts/python.exe -B -m unittest discover -s tests
```

Интеграционные тесты допускают только `127.0.0.1` и имя БД `ficbook_security_test`,
создают отдельные временные схемы и удаляют только их. Без этой переменной такие тесты пропускаются.
